# MCP 接入与游戏用例验证

工作台提供 MCP 工具，将 Codex 的截图、用例保存、录制和执行请求交给当前工作台的 Python 后端。游戏需要管理员权限时，由管理员工作台完成游戏操作，Codex 和 stdio 代理可以保持普通权限。

## 启动与接入

默认启动请求管理员权限并启用 MCP，只监听本机回环地址并保留随机凭证认证。已打开的旧版本需要先保存用例并正常关闭主窗口，再启动新版本。启动参数只应用于新实例；Python 启动入口会检查旧实例，并最多等待 10 秒确认 MCP 就绪。

1. 双击 `start.cmd`，或从安装版桌面快捷方式启动，确认 Windows UAC 权限提示后打开工作台，MCP 默认开启。`start_admin.cmd` 或开始菜单的「管理员启动」仍兼容。`start_admin_mcp.cmd` 仍兼容；已有普通权限工作台时，先保存并关闭，再以管理员启动。
2. 在工作台选择并连接要测试的游戏窗口。游戏输入仍需要已连接的客户端。
3. 双击 `mcp_info.cmd`，或运行 `runtime/node/node.exe scripts/mcp-connect-info.cjs`，复制打印的 `codex mcp add` 命令并执行。便携版使用项目内 Node 的绝对路径，包含空格的路径已经正确加引号，不需要系统安装 Node。
4. 在 Codex 设置的 MCP 服务器列表重启 `nycs-studio`，用 `/mcp` 确认连接。手动添加时选择 STDIO，命令与参数按打印结果填写。打印的 TOML 是同一配置的另一种表示；移动便携目录后需重新生成路径。

开始游戏截图、定位或执行前，先让游戏或工作台主窗口处于前台。工作台会先交接前台权限，再最小化自身并由后端激活连接的游戏；如果当前前台是其他应用，请先点击游戏或工作台主窗口，再发起首个游戏操作请求。

关闭当前工作台后，使用 `start_no_mcp.cmd` 可只关闭本次启动的 MCP；管理员启动可运行 `scripts/start-studio.ps1 -Admin -NoMcp`，直接调用 Electron 可传 `--disable-mcp`，Python 入口可传 `--no-mcp`。默认启动、`npm start` 和安装版快捷方式均请求管理员权限并开启 MCP。

Codex 支持 STDIO 与 Streamable HTTP MCP，并在同一主机的桌面应用、CLI 和 IDE 扩展间共享配置；设置中保存后需要重启对应 MCP 服务器。[官方 OpenAI MCP 文档](https://learn.chatgpt.com/docs/extend/mcp)

代理使用标准 MCP SDK，以 STDIO 对接 Codex，以 Streamable HTTP 对接已经启动的本机工作台。它不会另起 Python 后端、启动工作台或自行提权。MCP 协议版本由 SDK 与服务协商，支持的工具以实际 `tools/list` 结果为准。[标准 TypeScript SDK](https://github.com/modelcontextprotocol/typescript-sdk/tree/v1.x)

## 连接信息与作用域

开启后，工作台在 `.runtime/mcp-connection.json` 写入当前本机地址、随机凭证、进程 ID、版本和项目根目录。代理只接受属于同一项目的 `http://127.0.0.1:<随机端口>/mcp`，拒绝符号链接、过大的文件和无效凭证，不跟随 HTTP 重定向。

凭证由工作台启动时生成，通过 HTTP Bearer 发送。不要复制到 Codex 配置、聊天、日志或版本库；配置打印脚本只输出代理路径。关闭工作台后连接失效，下一次开启会生成新地址与凭证，重新启动 Codex 中的 MCP 服务器即可读取新信息。

MCP 提供下表中的工作台功能。连接限于工作台识别出的游戏窗口，用例限于 `test_cases`，模板限于该目录的 `assets`，报告工具限于工作台报告目录。普通键盘步骤拒绝 Windows 键及会切换系统窗口的保留组合，F12 保留为紧急停止键。显式添加的 [Python 脚本步骤](python-scripts.md) 会执行用例内的代码，使用后端的 Python 环境和权限；脚本可按这些权限访问文件、网络或导入第三方库。

## 工具与典型流程

| 工具 | 用途 |
|---|---|
| `nycs_status` | 读取管理员权限、游戏连接、录制和执行状态 |
| `nycs_windows` | 枚举工作台支持的游戏窗口 |
| `nycs_connect` | 使用刚枚举到的 `handle` 连接游戏，采用原生独立模式 |
| `nycs_capture` | 返回游戏客户端 PNG、尺寸和 `capture_id` |
| `nycs_save_template` | 使用观察过的 `capture_id` 和客户端像素矩形裁剪 PNG 模板 |
| `nycs_preview_target` | 预览控件定位，不发送输入 |
| `nycs_save_case` | 校验并保存指定名称和 `project` 的用例 |
| `nycs_load_case` | 读取已保存用例 |
| `nycs_run_case` | 按名称启动用例，可指定 1 到 10 次执行 |
| `nycs_events` | 按 `after` 序号增量读取事件，保留最后序号避免重复读取 |
| `nycs_report` | 按已完成执行返回的报告 `id` 读取结果 |
| `nycs_stop` | 停止执行或录制，并释放按住的输入 |
| `nycs_record_start` | 开始记录连接游戏中的手动输入 |
| `nycs_record_stop` | 停止录制，返回待检查的录制用例 |

先读 `nycs_status` 和 `nycs_windows`，再使用返回的窗口句柄连接。连接后截图确认角色、地图和任务状态。截图作为 MCP `image` 内容返回，尺寸等信息保留在 JSON 和 `structuredContent`；不需要通过文件路径猜测或另行抓取画面。

MCP 截图或定位预览成功后，工作台保持最小化，游戏继续处于前台，便于连续观察和执行。MCP 用例以 `passed` 完成时也保持这一状态。截图、预览或用例失败、执行停止及后端失联时恢复工作台，供检查错误；录制停止后仍恢复工作台处理录制结果。手动界面中的截图、预览和运行结束维持原有的界面返回行为。

用例与界面编辑器使用同一模型：`project` 包含 `name`、`schema_version: 1`、`selectors` 和 `steps`；控件可使用归一化坐标或 `assets/*.png` 图片模板。步骤使用控件名称作为 `target`，可配置等待、图片出现或消失断言，以及截图。保存前检查实际工具模式，服务会拒绝额外字段、失效控件引用和不允许的键盘组合。

图片控件新增可选字段：`templates: [{image, mask?}]`（最多 10 张附加模板）、`mask`（主模板遮罩）、`color_tolerance`（0～255 或 null）、`anchor`（图片 / OCR 控件名称，需同时配置相对 `roi`）。主模板、附加模板和遮罩都必须是 `test_cases/assets` 内的普通 PNG。设置 `recognition: "ocr"`、`text: "完成任务"`、`text_match: "exact"` 或 `"contains"` 可使用本地 OCR，此时不需要模板文件。旧用例省略这些字段时维持原有行为。

`nycs_preview_target` 可附带 `selectors` 数组提供锚点定义，当前 `selector` 会覆盖数组中的同名控件；缺失或循环锚点会被拒绝。预览未命中也返回截图、`matched: false`、`point: null` 和 `diagnostic`；`box` / `score` 可能属于未通过阈值或颜色校验的最佳候选。仅在 `matched: true` 时将 `point` 视为已定位结果。

将 `nycs_capture` 返回的截图矩形传给 `nycs_save_template` 时，坐标以游戏客户端左上角为原点，使用实际截图像素。不要使用整个桌面或 Electron 页面的坐标；不要复用别的截图的 `capture_id`。通过 `nycs_preview_target` 确认模板和 ROI 定位后再添加执行步骤。

保存后调用 `nycs_run_case`。启动成功只表示接受了运行请求；继续读取 `nycs_status` 和 `nycs_events`，直到真实执行结束，再获取报告并截图检查游戏结果。长用例在后台运行，使用轮询查看状态，无须把整个游戏流程塞进一个长 MCP 请求。

录制也走同一后端：开始录制后手动操作游戏，调用停止录制或按 F12，检查生成步骤后保存成用例。录制完成页仍可使用已有的「重放录制」。MCP 中可将检查后的录制结果保存，再按名称执行。

需要停止时直接调用 `nycs_stop`，或在本机按 F12。失联或请求超时时先检查运行状态；代理不会重试可能已经生效的游戏输入。断开代理不等于停止游戏用例，停止操作由工作台负责。

## 用「完成所有新手任务」验收

这个验收必须在真实游戏中逐项观察和执行。通过握手、工具列表或空用例只能说明接口连通，不能证明新手任务已完成。

1. 连接用户指定的初始角色，截图记录等级、地图、任务列表和当前教学提示。整理游戏实际显示的新手任务清单，记录每项的开始与完成条件。
2. 从截图中采集任务按钮、NPC 对话和教学控件，为任务推进编写短用例。先验证定位，再运行，并以执行后截图确认下一状态。
3. 对任务完成、奖励领取、教学结束和地图转移加入等待及图片断言。每完成一项，将已经验证的步骤合入完整用例，保留任务清单与截图证据。
4. 按实际任务清单检查所有新手主线、支线和必需教学是否完成；遇到缺失入口或不明确条件时记录未验证项，不能将一次点击成功作为完成依据。
5. 保存最终 `.nycs.json` 和 `assets` 模板，获取运行报告及结束截图。报告应注明验证过的初始状态、实际完成的任务、结束状态及剩余项。

新手任务完成后通常不可直接从头重放。若游戏未提供任务重置或另一个初始角色，应将本次验证标记为「分阶段实机执行验证」，完整重放保持待验证。只有从同样初始状态重放全部用例并检查结束条件通过，才可标记「完整回归通过」。

## 常见故障

- **未开启 MCP**：代理会提示先运行 `start_admin_mcp.cmd`。默认入口开启 MCP；若本次使用了禁用参数，需关闭主窗口后重新启动。代理不会自动替用户开启。
- **启动了旧工作台实例**：确认正在使用新增的 MCP 入口及其对应实例；现有实例未开启服务时，连接文件不会凭空出现。
- **工作台重启后连接失败**：重启 Codex 中的 `nycs-studio` MCP 服务器，让代理重读新连接信息，不要手工复制旧随机端口或令牌。
- **游戏操作仍失败**：检查 `nycs_status` 中后端管理员状态和连接窗口是否正确。这个接口解决的是 Codex 与管理员工作台之间的通信，游戏侧仍需工作台具备相应权限。
- **提示游戏失焦或无法激活**：先让游戏或工作台主窗口处于前台再重试。连续 MCP 截图和成功运行会保留游戏前台；手动切换到其他应用后，需要重新建立前台条件。执行中失焦仍会停止后续输入并记录错误。
- **只看见文本，没看见截图**：确认调用的是 `nycs_capture`，客户端支持 MCP 图片内容。服务与代理保留图片块，不将 PNG 编码塞进普通文本。
- **工具报参数错误**：读取当前 `tools/list` 的输入模式，检查控件引用、客户端坐标、文件名和键盘组合；不要绕过校验改用任意桌面或系统操作。
